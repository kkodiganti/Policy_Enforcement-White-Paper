## 2. Timing Gaps (Section 2.2)

1. **NIST SP 800-207, "Zero Trust Architecture"** — NIST, Aug 2020. https://nvlpubs.nist.gov/nistpubs/specialpublications/NIST.SP.800-207.pdf — Tier (a), Primary/Standards. Section 3 establishes every access decision is made and enforced per-request via a PDP/PEP pair rather than periodically; Section 5 explicitly separates the PEP's preventive/blocking role from logging/monitoring, which is forensic/detective by design. Core citation for the preventive-vs-detective distinction. (A fetch summary claimed CISA co-authorship alongside Rose/Borchert/Mitchell — **not independently confirmed, verify the PDF title page directly before stating co-authorship.**)
2. **Capital One 2019 breach, as a "detective, too late" example.** Krebs on Security, "Capital One Data Theft Impacts 106M People," July 2019. https://krebsonsecurity.com/2019/07/capital-one-data-theft-impacts-106m-people/ — Tier (c), named case study/primary journalistic reporting, fetched and verified directly. Breach occurred Mar 22–23, 2019; Capital One's own monitoring did not catch it — discovered ~4 months later via an outside tip (a GitHub user email, July 17, 2019). Root cause: an SSRF flaw in a WAF (ModSecurity) plus an over-permissioned IAM role, letting the attacker enumerate and read S3 buckets. The academic companion source — Khan, Kabanov, Hua, Madnick, *ACM Transactions on Privacy and Security* 26(1), 2022, DOI 10.1145/3546068 — is citation-confirmed only (403 on both dl.acm.org and the MIT DSpace mirror; full text not read).

   **⚠️ Author disclosure flag, not just a sourcing note:** this is Capital One's own breach, and the author of this paper (per its own byline/disclaimer) is a Capital One employee. Whether to use this as the paper's flagship timing-gap example — vs. citing it briefly and leaning on a different primary example, vs. omitting it — is a deliberate call for the author to make explicitly, independent of how good the source is. Flagged here rather than decided silently.
